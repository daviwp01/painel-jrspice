## 4. Tabela de Preços → Detalhes por Produto (commit `0d9f651`)

**Objetivo:** ao clicar num produto da página **TABELA DE PREÇOS**, abrir a página **DETALHES POR PRODUTO** já filtrada por aquele produto.

### Como funciona
- Slug `detalhes-por-produto` → componente `Dashboard/Show` (tabela `dashboard_pages`).
- A rota `GET /dashboard/page/{slug}` já aceitava `country_id` e `product_id` na query string → **nenhuma mudança de backend/banco**.
- Todo produto da PriceTable nasce de `products.country_id = <país>` (mesmo universo do sidebar do Show), então o `product_id` clicado nunca é descartado pela validação do controller.

### Arquivo alterado: `resources/js/Pages/Dashboard/PriceTable.vue`
- Nome do produto virou `<Link :href="route('dashboard.page', {slug})" :data="{country_id, product_id}">` (âncora real: nova aba, copiar link, teclado).
- Clique em qualquer célula da linha também navega, com guard `event.target.closest('a')` para **não disparar 2 requisições**.
- Feedback de carregamento reaproveitando o `isLoading` existente (tabela esmaece).
- Ícone `ArrowUpRight` no hover + `cursor-pointer`.

### Restrição temporária (somente masters)
```js
// resources/js/Pages/Dashboard/PriceTable.vue
// 🔒 RESTRIÇÃO TEMPORÁRIA ...
const isMaster = computed(() => !!pageProps.auth?.user?.is_master);

const canOpenDetails = computed(() =>
    isMaster.value &&
    (pageProps.dashboardPages || []).some(p => p.slug === DETAIL_PAGE_SLUG)
);
```
- **Para liberar a todos:** apagar apenas a linha `isMaster.value &&` (a checagem de permissão da página continua).
- Sem acesso, o nome fica texto simples (sem link, sem cursor, clique não navega).
- Camada extra no servidor: `InternalDashboardController` continua aplicando `canAccessPage()` (403).

### Por que NÃO passar `supplier_id` na URL
Em `Dashboard/Show`, `calculateMetrics`, `calculateChartHistorical` e `calculateChartWeekly` **ignoram** o fornecedor (só `getContinuousData` aplica) — passar o filtro geraria cards × gráficos divergentes. Com país + produto, tudo consulta o histórico completo.

### Por que NÃO usar `prefetch` (Inertia v2)
Cada prefetch é um GET completo que roda `logFilters`/`logSearch` e poluiria a analytics de buscas com "pesquisas" fantasma de hover. O ganho é irrelevante: destino responde ~90ms (26k preços indexados, métricas com cache 300s).

## 5. Tooltip Fixo no Gráfico (commit `c2756a2`)

**Objetivo:** o tooltip de "MELHOR PREÇO x TEMPO" **não deve acompanhar o mouse** — fica fixo no topo do gráfico e só atualiza o conteúdo.

### Arquivos
- **Novo:** `resources/js/Utils/FixedChartTooltip.js` → `createFixedTooltip({ align })`.
- **Alterados:** `resources/js/Pages/Dashboard/Show.vue` e `Demo.vue`.

### Configuração (idêntica nos dois)
```js
const fixedTooltip = createFixedTooltip({ align: 'center' }); // 'left' | 'right'

tooltip: {
    enabled: false,      // DESLIGA o tooltip padrão que seguia o mouse
    external: fixedTooltip,
    mode: 'index',
    intersect: false,
    callbacks: {
        title: (items) => { /* SEMANAL: mês da semana; demais: label do eixo */ },
        label: ..., labelColor: ..., labelPointStyle: ...
    }
}
```

### Comportamento atual
- Posição fixa: 12px do topo, centralizado (`align` configurável).
- Título do **mês sempre visível** — em SEMANAL o eixo só rotula no início do mês, então o tooltip usa a lista `weeklyMonthLabels` (52 semanas).
- Linhas: apenas os **anos com preço** no período (anos sem dado não aparecem, ex.: sem linha `2026: —`).
- Bolinhas com **borda branca 2px** (destaca o ano 2023, que é preto sobre o fundo `#0f172a`).
- Some quando o cursor sai do gráfico.

### Armadilhas do Chart.js (já resolvidas no código)
1. `tooltip.opacity` é **animado** → usar `tooltip.getActiveElements()` para decidir visibilidade (senão o tooltip "trava" visível).
2. `tooltip.dataPoints[i].label` é o **rótulo do eixo X** (ex.: "Mai"), não o preço → usar `tooltip.body[i].lines` (texto dos `callbacks.label`).
3. Sem `enabled: false`, o tooltip nativo continua sendo desenhado **junto** com o `external` (apareciam 2).
